Terms and technologies

AIArtificial intelligence

Software that performs tasks associated with human intelligence, such as recognising patterns, generating language or supporting decisions. Capability in one task does not imply dependable judgement in another.

Return to briefing ↑

Generative AI

AI that produces new content, such as text, images, audio or code, from patterns learned during training. A convincing answer can still be wrong.

Return to briefing ↑

Large language modelLLM

An AI model trained on large amounts of language and other data to generate and process text. It can support dialogue, but its output is not an authoritative record of facts.

Return to briefing ↑

Conversational AI

AI designed to interact through dialogue, allowing a person to ask questions, clarify a need and build on earlier exchanges.

Return to briefing ↑

Agentic AI

AI systems arranged to pursue a goal through multiple steps, often using tools. The degree of independence depends on design, permissions and approval rules.

Return to briefing ↑

AI agent

Software that uses an AI model to choose steps and use available tools toward a goal. An agent can have limited authority; being called an agent does not establish autonomy or reliability.

Return to briefing ↑

Personalisation

Adapting responses or services to a person’s preferences or circumstances, using information the system is allowed and able to access.

Return to briefing ↑

Memory and context

Context is information available for a particular interaction. Memory is information a service may retain for later use. What is retained, used or forgotten depends on product settings, limits and permission.

Return to briefing ↑

Plugin

An installed extension that gives an assistant particular instructions, tools or services. Some connect to an external account. Installing one does not authorise every action or guarantee that it will be recommended.

Return to briefing ↑

APIApplication programming interface

A defined way for one software system to request information or an action from another. Access rules, data quality and business authority still need to be established.

Return to briefing ↑

MCPModel Context Protocol

An open standard for connecting AI applications to external information, tools and workflows. It is a connection mechanism, not a permission to transact or proof of autonomous agency.

Return to briefing ↑

A2AAgent2Agent

An open protocol through which separately operated AI agents can exchange messages, tasks, status and results. It can complement MCP. Ordinary software integration does not automatically require it.

Return to briefing ↑

Structured or machine-readable information

Information organised into explicit fields and relationships that software can interpret, such as a business’s name, location and service capabilities. Structure helps interpretation; it does not guarantee accuracy or discovery.

Return to briefing ↑

AI-mediated commerce

Commercial discovery, comparison or interaction in which AI helps connect a customer with a business. Checkout may occur inside an assistant, in an embedded browser or on a separate merchant website.

Return to briefing ↑

Authorisation

Permission for an identified person or system to perform a specific action within defined limits. Access to information is different from authority to accept a price or place an order.

Return to briefing ↑

Human approval

A person explicitly checks and permits a proposed action before it takes effect. The person needs the relevant information and authority; a vague approval prompt is not a substitute for review.
