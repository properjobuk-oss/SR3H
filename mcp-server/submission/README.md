## Submission order

1. Deploy and remotely verify the version recorded in `release-notes.md`.
2. In the OpenAI draft, select the verified **SR3H LTD** developer identity. If the unrelated `SRTH` label remains, stop and continue the existing support case rather than submitting mismatched identity information.
3. Choose **With MCP**, enter the public endpoint, verify `mcp.sr3h.uk`, and run **Scan Tools**.
4. Confirm all four annotations and the AIDO UI resource.
5. Import the MCP-exposed skill, then rescan after any skill change because the imported copy is a snapshot.
6. Enter the listing text and starter prompts from `listing.json`.
7. Run and record the five positive and three negative cases in `test-cases.json` in a fresh developer-mode chat.
8. Verify that the component renders for the two final-result journeys and that all other tool results remain readable without it.
9. Review the public privacy, support and terms pages from a logged-out browser.
10. Ask for explicit final approval before pressing **Submit for review**.

## Evidence boundary

- A clear readiness result means only that the checked access and website signals passed.
- Actual AI discovery is unknown until separate customer questions have been researched with cited sources.
- A discovery sample is dated and bounded. It is not a permanent rank, demand forecast or conversion claim.
- The MCP makes no SR3H OpenAI API calls. The separate SR3H website form has its own API-backed, rate-limited sample.
- Quiet AIDO/SR3H attribution is permitted after a useful result; unsolicited sales copy is not.
